# Text Explain — 浏览器扩展

划中网页上任何一段看不懂的话，本地 DSH 用大白话讲给你听；可以接着追问，也能把它交给 DSH 里继续。与 DSH 插件「划词解释」共用同一套后端和同一套三档讲法。

## 安装（未打包，开发者模式）

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录（`dsh-text-explain/extension`）

> Edge 同理：`edge://extensions/`。
> 注意选**本目录这一层**（里面有 `manifest.json`），不要选它的上一级。

装好后它的 ID 应当是 **`flllhbaameongigaidcdonkdinpajaid`**（由 `manifest.json` 里的 `key` 固定，换机器也不变）。

## 在 Firefox 上用

**源码完全共用**——因为 Firefox 也支持 `chrome.*` 这套命名。唯一的硬差异在 manifest 的后台写法：

| | Chrome / Edge（MV3） | Firefox（MV3） |
| --- | --- | --- |
| 后台 | `"service_worker": "background.js"` | `"scripts": ["background.js"]` |

所以本目录里有两份 manifest：`manifest.json`（Chrome/Edge 用）与 `manifest.firefox.json`（Firefox 用，由 `node extension/build-firefox-manifest.cjs extension` 生成）。

**试用（立刻能跑）**：

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点 **临时载入附加组件**
3. 选中本目录里的 **`manifest.firefox.json`**

> ⚠️ 临时载入的扩展**关闭浏览器就没了**——只适合试用与调试。

**正式发布**：上架 [AMO（addons.mozilla.org）](https://addons.mozilla.org/developers/)——**免费**，审核通常几小时到几天。打包时把 `manifest.firefox.json` **改名成 `manifest.json`** 再压成 zip 上传（其余文件照旧）。

## 打包成 zip

```powershell
# 1) 生成 Firefox 版 manifest
node extension/build-firefox-manifest.cjs extension

# 2) 各打一份：Firefox 那份记得把 manifest.firefox.json 改名成 manifest.json
Compress-Archive -Path extension\* -DestinationPath dist\text-explain-firefox.zip -Force
```

## 用法

**默认走右键菜单**（日常浏览最不打扰）：

> 选中一段文字 → **右键** → **「用大白话解释『…』」** → 浮窗里流式出解释

浮窗里可以：

| 操作 | 说明 |
| --- | --- |
| **追问** | 底部输入框回车即可多轮追问；模型记得前面聊过什么 |
| **切档位** | 顶部 小白 / 通识 / 专业 —— 切了会**用新讲法重讲第一个问题** |
| **📌 钉住** | 点一下，浮窗**不再随点击页面而关闭**（只认 `Esc` 或 `×`）——防止误触 |
| **关闭** | `Esc` 或右上角 `×` |

若您更想要「划词就冒按钮」，到设置里把**触发方式**改成「划词后浮出小按钮」或「两者都要」。

### 有的网站划不动字？

有些网站**明文禁止选中文字**（多半是怕被复制）——你拖过去它不变蓝，右键菜单也不出现（我们的菜单只在「有选区」时才出现）。于是最尴尬的一幕就来了：**看不懂的那句话，偏偏问不了。**

**默认开着「解锁划词」**，扩展会替你把那层封印掀开。它掀的是两样东西：

| 网站的手法 | 我们怎么应对 |
| --- | --- |
| CSS 说「不许选」（`user-select: none`） | 注入一条优先级更高的规则压过去 |
| JS 拦下 `selectstart`（选中的第一步） | 在**捕获阶段**按住那个拦截器（只按住它，不碰选中的正常流程） |

**关得掉**：设置页 → **高级设置** → 「解锁划词」。掀封印是有代价的——地图、拖拽排序这类界面上可能多出「选中蓝」，觉得别扭就关掉它。

**它刻意不做的事**：

- 不碰网站的复制按钮，也不改它的任何数据；
- 不去拦 `mousedown`——很多站点的按钮、拖拽、播放器全靠它，拦了会把正常操作一起弄坏；
- 不覆盖选中颜色（`::selection`）——那会波及所有网站的观感，为治少数站点而改全网不划算；
- 不新增任何权限。

**仍然划不动的**：字若是**画出来的**（canvas：在线文档、地图、在线 Office）或干脆是**图片**（漫画、扫描件），页面里根本没有文字，谁都取不到。这类只能自己手打或复制进来问——「手动输入」这条兜底路已列在计划里。

## 网页上下文（它凭什么看懂「它」）

单独看一句「它指的是这个」，谁也不知道「它」是什么。所以打开浮窗时，扩展会顺手取三样东西，拼在**第一条消息**里一起发给模型：

| 取什么 | 作用 |
| --- | --- |
| **所在段落的原文**（上限 1200 字） | 让模型看出「它 / 这个」指什么 |
| **最近的上级标题**（h1–h6） | 一句话说明这一节在讲什么 |
| **页面标题 ＋ 网址** | 定位出处 |

**只取选区附近那一小段，不传整个网页。**

## 三种后端：本机 DSH / 免费模型 / 你自己的 API

设置页顶部选一个：

| | **本机 DeepSeek Harness**（默认） | **免费模型** ⭐ | **我自己的 API** |
| --- | --- | --- | --- |
| 连什么 | 电脑上的 `dsh-text-explain` 插件 | 预设好的免费服务商：智谱 GLM-4.7-Flash、通义千问、Gemini、Groq、OpenRouter、本机 Ollama / LM Studio | 任意 **OpenAI 兼容**接口 |
| 要准备什么 | 装好并运行 DSH | **只填一个免费 Key**——地址与模型名已自动配好 | 地址 ＋ 模型名（＋ Key） |
| 三档讲法 | 由插件提供 | **扩展内置**（措辞与插件一致） | **扩展内置** |
| 模型名 | `text-explain-plain` 等 | 已预设，不用管 | 你填（`deepseek-chat`、`gpt-4o-mini`、`llama3.1`…） |
| API Key | 不需要 | **要（免费申请）** | 需要时填，**本地模型留空即可** |
| 🌐 联网搜索 | ✅ | ❌ 不出现（联网是 DSH 提供的能力，第三方 API 不带） | ❌ 同左 |
| 交接 | 可在 DSH 里开新会话 | 复制一份 Markdown 交接单 | 同左 |
| 花钱 | 不花（用你自己的 DSH） | **不花**（服务商的免费层） | 看服务商 |

**「免费模型」是怎么免费的**：这些服务商自己提供免费额度，你去它官网注册就能拿到 Key——扩展把**地址与模型名都替你填好了**，你只需要申请一个 Key 粘进来。

**推荐顺序**（免费那一档里）：⭐**智谱 GLM-4.7-Flash**（长期 0 元、**国内直连**）→ 通义千问（每模型 100 万 token）→ 本机 Ollama / LM Studio（**完全离线，数据不出电脑**）→ Gemini / Groq（**需要代理**）。

### 免费模式也有代价，得知道

- **会换代**：免费模型下线后，请求会被自动路由到新版，模型名可能要改。
- **注意隐私** ⚠️：**免费服务通常会用你的数据改进模型**。介意的话，用「本机 DSH」或本机 Ollama / LM Studio。
- **能力有差**：免费模型解释「小白 / 通识」两档够用；「专业」档要更细的机制与取舍，可能力不从心。
- **国内可达性**：智谱、通义、Ollama、LM Studio **直连**；Gemini、Groq **要代理**。

**为什么能兼容各家**：它们讲的是**同一套协议**（OpenAI 的 chat-completions）。扩展不认厂商，只认协议——所以预设里那几家、以及任何自建服务，填上地址就能用。

### 关于权限

MV3 的扩展**不能事先拿到全网权限**。所以本扩展声明的是 `optional_host_permissions`：**你保存自定义地址时，浏览器当场只申请那一个域名**，而不是一上来就要「访问所有网站」。

### 两个兼容性开关（高级）

- **把系统提示并入第一条消息**：有些本地模型不认 `system` 角色，勾上它讲法照样生效。
- **不用流式输出**：少数服务不支持 SSE，勾上改为整段返回（等待感会差些）。

## 设置

点扩展图标（或扩展详情页的「扩展程序选项」）打开设置页：

| 项 | 说明 |
| --- | --- |
| **什么时候出来** | `只在右键菜单里`（默认）／`划词后浮出小按钮`／`两者都要` |
| **本机后端地址** | 默认 `http://127.0.0.1:3080/api/text-explain/v1` |
| **默认讲法** | 三档之一；浮窗里仍可临时切换 |
| **解锁划词**（高级） | 默认开：在「禁止选字」的网站上也能划中。代价与边界见上节 |
| **测试连接** | 当场打一次 `/models`，一眼看出后端通不通 |

改设置**立即生效**，不用刷新页面。

## 它是怎么工作的

```
网页 ──划词/右键──► content.js（Shadow DOM 浮窗）
                       ├─ 收集网页上下文（段落/标题/页面）
                       ├─ 维护对话历史（追问）
                       │  chrome.runtime.sendMessage
                       ▼
                   background.js（service worker）
                       ├─ chrome.contextMenus 右键菜单
                       └─ 发 fetch：POST /chat/completions (stream)
                       ▼
                   本机 DSH 的 dsh-text-explain 插件
                       │  SSE 分片
                       ▼
                   浮窗逐片渲染（markdown.js）
```

### 四个关键设计

**① 请求在 background 里发，不在页面里发。**
内容脚本跑在网页自己的来源下，它发的 `fetch` 会带上那个网站的 `Origin`，被浏览器的跨源策略拦下（我们不可能、也不该把全网加进后端白名单）。service worker 的 `fetch` 带的是扩展自己的来源，配合 `host_permissions` 即可直连本机后端。

**② 界面放在 Shadow DOM 里。**
既不让页面的 CSS 污染浮窗，也不把我们的样式洒进别人的页面。

**③ 渲染前先转义 HTML。**
浮窗里的文字来自模型，而模型看到的是网页内容——不转义就等于把任意网页内容当 HTML 执行。

**④ 上下文只取局部。**
目标是让模型看懂那一句话，不是把用户在看什么整个交出去。

## 后端白名单

由于走的是 service worker + `host_permissions`，通常**不需要**登记来源。若 DSH 端返回 `origin not allowed`，把扩展 ID 按下面格式加进 `<DSH_HOME>/text-explain/settings.json`：

```json
"allowedOrigins": ["chrome-extension://flllhbaameongigaidcdonkdinpajaid"]
```

该文件**改完即刻生效**，不必重启 DSH。

## 安全

- 扩展只申请 `storage` 与 `contextMenus` 权限，以及 `127.0.0.1:3080` 的访问权；不读取、不外传任何网页数据。
- **永远不提供「读本地文件」能力**：网页内容是不可信输入，一旦与本地文件读取同处一个上下文，就是提示注入的入口。
- **「解锁划词」不新增权限**：它只是在页面里注入一条 CSS 与一个事件监听，掀掉网站「禁止选中」的封印；不碰复制、不改数据、不外传。
- 落盘内容仅限本机偏好（触发方式、默认讲法、交接方式、后端地址与 Key、解锁划词开关）——都在这台电脑的浏览器里，不含任何网页内容。
